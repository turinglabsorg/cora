# cora — agent notes

Always-on Discord agents with personalities, layered memory, routines and their own Docker desktops. See `README.md` for the architecture and `DESIGN.md` for the panel's design system (read it before any UI change).

## Layout

- `src/main.js` wires everything; `startCora(overrides)` is what the tests start.
- `src/discord.js` persistent Gateway (heartbeat, resume, reconnect) + REST + per-channel `cora` webhooks; the same class runs each agent's own bot (presence-only intents, `say`, `syncProfile`).
- `src/agent-bots.js` one connection per agent with a `CORA_BOT_<NAME>` token: posting, typing, mentions and profile sync as that agent; listening stays on the main bot.
- `src/channels.js` where the cora lives: Discord or Telegram (`settings.transport`), one at a time, plus the panel rooms; `info(id)` gives prompts the `where`/`place` of a channel. Telegram channel ids are `tg:<chat id>`.
- `src/telegram.js` Bot API client (getUpdates long polling, HTML messages, files); `src/telegram-bots.js` agents' own Telegram bots (`CORA_TG_BOT_<NAME>`, send only).
- `src/secrets.js` writes a token pasted in the panel into hush (`hush box seal` to the machine's own key piped into `hush box open`). The CLIs never inherit `CORA_BOT_*`.
- `src/orchestrator.js` who answers and when: named agents answer alone and keep the conversation for follow-ups (`FOCUS_MS`), a mention of a non-agent wakes nobody, a human always gets an answer (a named agent that passes is asked again), chattiness gates the rest, `maxAgentTurns` stops agent-to-agent loops, only `settings.guildIds` are heard. Turns get `say` (post now), an inbox of messages written meanwhile (steering, delivered with tool results) and an automatic acknowledgement when a called agent stays silent. A round frees its channel after `releaseAfterMs` (20 s) while agents on a task keep working in the background (`state.working`: they get new messages through the inbox, never a second turn). `resumeInterrupted()` picks up after a restart the computer tasks that were running (traces are saved every 30 s while they run).
- `src/brain.js` prompts and the tool loop; `elsewhere()` adds the agent's latest exchanges in its other places to every turn; `sleep()` is the nightly memory consolidation. The loop is the **Cora harness**: a task (a turn with the agent's computer, or a routine) runs until done (bounds 8 hours / 5000 steps); an agent that stops with nothing, with "shall I continue?" or with what it is about to do (`unfinished()`) is sent back to work, a finished one confirms once (`DONE`), the same tool call with the same arguments 4 times in 10 is a loop and is refused, long conversations are summarised by the agent (`COMPACT_CHARS`), a silent agent is reminded to send an update every 15 minutes. The same checks rerun Claude Code / Codex when they stop early. `resumeTurn()` restarts a task cut short by a restart.
- `src/rooms.js` the panel's chat rooms (`web` salotto, `web-<agentId>` private); `src/traces.js` records each turn's reasoning (steps streamed over SSE, saved in the `traces` table).
- `src/memory.js` retrieval (pinned + FTS5 relevance + recent). `src/store.js` is the only place that touches SQLite (`~/.cora/cora.db`).
- `src/llm.js` providers: `claude/`, `codex/` and `hermes/` run CLIs (`src/cli.js`), which call cora's tools through `src/mcp-server.js` → `src/bridge.js`; `ollama/` (Ollama Cloud) and `orcarouter/` (OpenAI-format router, `routerChat()`, key `ORCAROUTER_API_KEY`) run on the Cora harness. Hermes runs one-shot with `-t cora` only (never its terminal, file or computer-use toolsets) and `--ignore-rules`, in Cora's own Hermes home whose `config.yaml` (`hermesConfig()`) takes the bridge session from `${CORA_BRIDGE_URL}`/`${CORA_BRIDGE_TOKEN}`; `bin/hermes-smoke.mjs` checks it live. No API-key providers for Claude/ChatGPT: the owner wants the subscriptions. argo-* models belong to another project and are never listed for Hermes. Model ids are `provider/model` with the provider in `MODEL_PROVIDERS` (`src/store.js`); the panel lets the owner type an id the list does not show.
- `src/tools.js` agent tools. Always: `say`, memory tools, `notify`, `ask_owner`. Only when an owner started the conversation or in routines: desktop tools and the agent's own routines (`list_routines`, `set_routine`, `delete_routine`).
- `src/box.js` docker CLI for the desktops (`cora-box-<agentId>`, volumes `cora-home-<agentId>` and `cora-sys-<agentId>` for Tailscale state and SSH host keys, noVNC on a random 127.0.0.1 port, sshd on the agent's fixed `sshPort`); outdated boxes are recreated when cora starts or from «Aggiorna».
- `src/push.js` Web Push (VAPID + aes128gcm) to the owner's devices; agents' `notify` tool and panel requests. `ask_owner` posts where the conversation is (`Orchestrator.askOwner`): a Discord/Telegram channel (owner mentioned, answers as text, no Web Push) or a panel room (buttons + push); the owner's next message there is routed to the asking agent (`state.request` in `address()`).
- `src/web.js` panel API, SSE, password login (HMAC cookie, `X-Cora` header + Origin check on writes), authenticated noVNC proxy at `/box/<agentId>/`.
- `web/` vanilla JS panel, no build. `box/` the desktop image (Debian, XFCE, Chromium, x11vnc, noVNC).
- `src/pass.js` passes from usecora.space: Ed25519 key derived from `CORA_CLOUD_SEED`, `signPass`/`verifyPass` (audience = the space's host, one minute, single use). `src/web.js` turns a pass (`/auth/cloud`) or a one-time link made on the host (`/auth/link`, `bin/login-link.mjs`) into the panel session; with `CORA_CLOUD_URL`/`KEY`/`SPACE` set the password login is off. With only `CORA_CLOUD_KEY` (set in the installation's non-secret `~/.cora/env`, read by `bin/run.sh`), `POST /api/cloud/notice` accepts notices signed by the cloud (audience `notices`, e.g. a waitlist sign-up) and posts them as "Cora" in the Discord channel named in `settings.noticeChannel` (default `waitlist`); the cloud sends them to the space named in `CORA_CLOUD_NOTIFY`.
- `cloud/` usecora.space: `src/app.js` routes by Host (apex = landing + sign-in, `<space>.<domain>` = proxy to that space's Cora), `src/oauth.js` Google/GitHub with PKCE, `src/store.js` accounts, identities, invites, spaces, requests, waitlist (`~/.cora-cloud/cloud.db`), `src/views.js` the pages (English only; the landing has no sign-in links until sign-in opens, `POST /waitlist` takes an email and a company), `web/` their CSS/JS, `cli.js` adds spaces by hand and lists the waitlist. Tests in `test/cloud.test.js`.

## Rules

- Secrets only through hush (`bin/run.sh`). Discord: cora listens through an agent's own bot with the Message Content intent, or an optional dedicated `CORA_DISCORD_LISTENER_TOKEN`; it never borrows another tool's bot. Telegram: `CORA_TELEGRAM_BOT_TOKEN` and `CORA_TG_BOT_<NAME>`, stored from the panel through `src/secrets.js`. Bot API URLs carry the token: never log them.
- The agents are not tied to a platform (the owner asked): prompts say where they are right now, never that they "live on Discord".
- Bots can be in servers the agents must not hear: only `settings.guildIds` are heard, keep everything else out of it.
- No runtime dependencies; add any through the mcaifee gate.
- The CLIs must never get tools that act on the host: Claude runs with `--tools ""`, Codex with `-s read-only` and shell/unified_exec/browser/computer-use/multi_agent disabled (its code mode stays on because MCP calls go through it; verified it cannot read host files). Re-verify with a live probe after CLI upgrades.
- Agents get the owner's `~/.agents/AGENTS.md` in their system prompt (the owner asked for it explicitly). Do not strip it.
- Every behaviour change needs an integration test in `test/cora.test.js` (stand-in Discord, Ollama and docker in `test/helpers.js`).
- UI copy is written in Italian and translated through `web/i18n.js` (English); content written by people or agents is wrapped in `raw()` and never translated. Code, comments and docs are English.

## Deployment

usecora.space runs on the host behind the grog relay (`~/.grog/sites.json`: the apex and each space name point at the cloud's port 4380) with `cloud/bin/start.sh`; each space's Cora gets `CORA_CLOUD_URL=https://usecora.space`, `CORA_CLOUD_KEY` and `CORA_CLOUD_SPACE`.

Runs on a macOS host as the LaunchAgent `org.turinglabs.cora` from `~/Services/cora`, listening on 127.0.0.1:4370; put it behind your own HTTPS tunnel or reverse proxy. Deploy with `CORA_DEPLOY_HOST=user@host deploy/macos.sh` (it rebuilds the desktop image only when `box/` changed).
